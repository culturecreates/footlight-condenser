**Stage: QA-only keyed ResourceList acceptance PASSED; automatic/live discovery NOT implemented.** On 2026-11-27 the isolated staging-derived PostgreSQL database was exercised: the QA clone contained 102 sources, 22 webpages and 396 statements. The saved-input bilingual keyed DSL/atomic ResourceList adapter was actually applied to the QA clone: **8 English URLs / 8 French URLs / 8 matching RDF identities; 0 webpages created**. Original and QA-copy post-import graph parity each returned **PASSED; +0/-0**. The nine-file focused Rails regression suite also passed **63 runs, 245 assertions, 0 failures, 0 errors, 0 skips**, in a single run on Rails 8.0.2/PostgreSQL 17. This is not evidence of complete live pagination, new-event RDF identity minting, unattended refresh scheduling, or full production readiness; keep PR in draft while deciding production scope.

## Goal

1. Copy working `dansedanse-ca` to `dansedansetest-ca` (same database, different Website/Source/Webpage IDs and **different RDF URIs**).
2. Keep original and copy's source URLs, full bilingual event inventory, all non-ResourceList DSL, selected statements and review state equivalent.
3. Change **only** ResourceList pairing extraction in the copy to `get_sorted_calendars` after that DSL and its shared multi-language refresh context have been implemented.
4. Refresh copy only; compare every final statement and normalized Artsdata graph with original; never publish the copy.

## QA copy implementation in draft PR

- Website detail on staging/development has "Copy website for QA" with proposed seedurl `dansedansetest-ca`.
- Clone service creates a new Website, Sources, Webpages, Statements, preserves bilingual grouping, and remaps all site-owned RDF URI identities. Public Webpage URLs intentionally remain **identical**.
- Copy is unscheduled (`schedule_every_days=nil`, `schedule_time=nil`, `last_refresh=nil`), unmonitorable, and its direct Artsdata export is prohibited. Promoting it to active through normal rollout is blocked.
- Cross-site ResourceList discovery targets cause clone creation to **fail closed** pending explicit mapping.
- Jobs enqueue Webpage IDs; ambiguous URL-only refreshes fail. Public URL-only graph queries exclude test copies unless website ID explicitly supplied.
- ResourceList import rejects original-site RDF URI values regenerated by the old URI-list DSL. This may prevent early copy refresh: that is an **expected safety block**, not pairing success.
- New case-insensitive DB seedurl unique index: inspect staging duplicates before applying the migration.
- Service is atomic and does not enqueue refresh/publish jobs. No automatic clone creation is performed by this PR.

   It reports key conflicts, unmatched pairs, existing RDF URI conflicts and changed URL inventory compared to the copy's stored English ResourceList caches. A manifest is NOT an end-to-end parity pass.

6. **QA-only shared DSL integration (validated and applied to the 8-event QA clone):** `get_sorted_calendars=urls,en` or `get_sorted_calendars=uris,fr` is authorized only with a validated shared `DanseDanseKeyedQaRefresh::Context`, bound to the specific shadow QA copy. Ordinary DSL runs without this context fail closed.

   After capturing and reviewing the read-only manifest and saving contemporaneous HTML, use the **isolated QA database only**:

   ```bash
   DATABASE_URL="postgresql:///footlight_condenser_dansedanse_qa" \
   ```

   This defaults to **read-only validation**. It checks both language inventories and exact manifest pairs, all currently existing event URL/RDF identities, and the selected ResourceList statements. It does not create any event pages.

   If and only if read-only validation and focused tests pass, repeat the command with `--apply`. That atomically writes only QA ResourceList cache values and calls the existing `AddWebpagesJob` import validator with `refresh_new: false`; it rejects unexpected new pages, so this initial tranche supports **existing eight pairs only**, not production discovery or minting. No scheduling or event statement refresh is performed.

   Before and after applying, compare the original and QA copy with `script/danse_danse_shadow_parity.rb compare`, retaining distinct report paths. Validate that the copied ResourceList caches now hold the same ordered RDF URIs in both languages.

   **Still to implement:** live fetched-pagination completeness proofs, general-purpose `get_sorted_calendars` for other sites, source-configured automated bilingual refresh scheduling, and reviewed URI minting for new events. None should be enabled by this QA script.
7. When the new DSL is implemented, change only the copy's ResourceList algorithm; use recorded equivalent input HTML, refresh both calendars then the event statements on the copy, and verify no original statements changed.
8. Compare final state:

   `SHADOW_SITE_SEEDURL=dansedansetest-ca bin/rails runner script/danse_danse_shadow_parity.rb compare /tmp/danse-danse-baseline.json /tmp/danse-danse-qa-report.json`

   The snapshot records test-copy provenance; comparator maps the **known deterministic** test RDF URI namespace and copied Source IDs back to original identities. Non-ResourceList DSL, selected values, statuses, manual flags, archive dates, URL inventory and RDF graph must match.

## Pass criteria

- Original website unchanged (verify before/after original snapshot).
- No cross-site jobs, no original-source data mutations, no clone publication or scheduling.
- Complete FR and EN pagination (fail if one side incomplete).
- No key ambiguity and no silent dropping of unmatched translations.
- Equal event counts and correct FR/EN URI groupings.
- Zero final selected-statement differences (all properties, including optional data).
- Zero added or removed RDF graph statements after only test identities are normalized.

## Local PostgreSQL test bootstrap: reusable command (2026-11-28)

Repeated PG17 attempts in both keyed QA and pagination worktrees encountered
test schema purging `pg_stat_statements` (superuser extension), followed by
partial-load `heroku_ext` duplication. The keyed QA worktree now has
`script/run_keyed_qa_tests.sh`. It is **local-only**, tied to PostgreSQL
socket `/var/run/postgresql`, port `5433`, branch
`feat/keyed-resource-list-alignment`, and **only** the disposable database
`footlight_condenser_keyed_qa_test`. It does **not** use either the Danse
Danse development QA copy or any staging database.

First use: inspect the script, then run:

```bash
git pull --ff-only
bash script/run_keyed_qa_tests.sh --status
bash script/run_keyed_qa_tests.sh --reset
```

`--reset` intentionally **deletes and recreates the named test database**,
creates the required extension as PostgreSQL superuser, loads the Rails schema
once as the normal OS/database user, validates readiness, then runs the
four focused pairing preview suites. No `pg_stat_statements` privilege
grant or disabled foreign keys is needed. This mode is an explicit one-time
bootstrap, **not** the default.

Subsequent runs leave the test database intact and only execute tests:

```bash
bash script/run_keyed_qa_tests.sh
```

The script refuses wrong branch, overridden database URLs, nonlocal
PostgreSQL host, unexpected port, and non-test Rails environment. If
the schema isn't ready, the default mode fails with instructions instead
of silently resetting the database.

**Verification status:** committed code; the bash script has been
syntax-checked with `bash -n`, but the actual PostgreSQL reset and the
Rails suites require a run in the user's WSL environment.

## Legacy controller fixtures versus isolated preview tests (2026-11-28)

A local run of the original four-suite command reached **118 runs, 55 assertions,
0 failures, 103 errors**. The dominant failure occurred **before test setup**:
Rails 8.0.2 `ActiveRecord::FixtureSet` inserted legacy fixtures containing
`properties.rdfs_class_id=980190962`, while the corresponding
`rdfs_classes` parent was not yet loaded. On PostgreSQL 17, Rails' usual
`DISABLE TRIGGER ALL` around fixture insertion requires superuser privilege.
The existing app user is deliberately not granted that privilege.

The 3 *new* pairing UI checks have therefore been moved out of
`test/controllers/websites_controller_test.rb` into
`test/integration/danse_danse_pairing_preview_test.rb`, with
`self.fixture_table_names = []` and a small FK-valid ActiveRecord-built
setup. The QA-only runner now executes this file together with the three
ResourceList-specific suites, **not the entire legacy controller test file**.

This isolates and unblocks *new feature verification*; it does not fix the
preexisting global legacy fixture dependency. The remaining legacy controller
suite must be repaired separately with FK-valid fixture creation/loading,
without granting superuser privileges, disabling actual database FK constraints,
or changing the Artsdata export contract.

**Verification:** this revised test selection was committed but has **not yet**
been run successfully in the user's WSL checkout. Do not interpret it as
